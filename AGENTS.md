# Fail-Closed Blast Doors: notes for agents

A Harmony mod that makes the blast door (`StructureBlastDoor`) close when it loses power.
[README.md](README.md) says what it does, the accumulator model, and the public API. Read it
before changing behaviour: the rules interlock (charge, the `c >= t` close gate, `Setting` as
the pending-close store).

## Commit trailers

Every commit an agent makes ends with one trailer:

```
Assisted-by: AGENT_NAME:MODEL_VERSION [TOOL1] [TOOL2]
```

- `AGENT_NAME` is the agent, `MODEL_VERSION` the exact model that made the change, e.g.
  `Assisted-by: Claude:claude-sonnet-5-5`.
- The bracketed tools are optional: the square brackets in the format line mark them as
  optional and are not written. For example
  `Assisted-by: Claude:claude-sonnet-5-5 dotPeek UnityPy`. List only specialised analysis tools used for the change
  (for example a decompiler such as dotPeek, or UnityPy for reading prefab data), never
  everyday tools like git, dotnet or an editor.
- Never add `Co-Authored-By` or `Signed-off-by` lines. Those are for people.

## Working in this repo

- **Versioning.** `About/About.xml` is the single source of the mod ID and version: the build
  generates `ThisModInfo` from it (the `GenerateModInfo` target in `Main.props`). To release,
  bump `<Version>` there and push a matching `v<version>` tag; CI rejects a mismatch.
- **Local paths.** The game's DLL folder and the install folder go in the gitignored
  `Local.Developer.props`. Local installs go to LaunchPad's mods folder
  (`%USERPROFILE%\Documents\My Games\Stationeers\mods\FailClosedBlastDoors\`), never
  `BepInEx/plugins`. `dotnet build Main.csproj -t:Install` does the copy.
- **LaunchPad needs `About/thumb.png` and `About/Preview.png`.** They are generated by
  `python tools/make_images.py` (Pillow); edit the script, not the PNGs.
- **Private game members.** `Main.csproj` publicizes `Assembly-CSharp`, so the code names
  private members directly: `Door.doorAnimComponent`, `BinaryAnimComponent.t`,
  `InteractableAnimComponent.time`. After a game update, check those first.
- **The decompiled source** is outside this repo, at
  `C:\Users\erica\Source\Decompilation\Stationeers\Assembly-CSharp`. Search it rather than
  guessing paths. The classes that matter: `Door.cs` and `Airlock.cs` (under
  `Assets\Scripts\Objects\Structures\`), and, at the root of the decompile,
  `InteractableAnimComponent.cs`, `BinaryAnimComponent.cs`, `DoorAnimComponent.cs`.
- **Scope.** Everything is gated on `BlastDoorApi.IsBlastDoor` (an exact prefab name match):
  `Airlock` is the base class of the airlock gates and of modded doors, so a type check would
  be too broad. `Thing.IsOpen` and `Thing.Error` are cached per frame; the tick uses
  `InteractOpen.State` instead.
- **The animation is symmetric.** One `time` serves both directions, so the slow open is done
  by setting `time` in a prefix on `RefreshState` just before each animation starts.
- **Threads.** Power is computed off the main thread in places, so `BlastDoorApi` readers only
  read values the main-thread tick cached. Keep it that way.
- **Not verified in game yet.** Written against the decompile and compiled, but not run: the
  prefab's real `time`, whether it has an error state (`HasErrorState`), whether its colliders
  follow the animation, and what turns `Setting` into movement in the keypad's Logic mode.
  The first in-game run should log those.
- **CI.** `.github/workflows/deploy.yml` downloads the dedicated server's DLLs with
  steamcmd, builds against them, and on a `v*` tag attaches a zip of the DLL and `About/` to a
  GitHub release. The layout follows the modding Discord's pinned
  [stationeers-example-mod](https://github.com/aproposmath/stationeers-example-mod).
